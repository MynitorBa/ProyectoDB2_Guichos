1 Requisitos Previos

Antes de clonar el repo necesitas tener instaladas estas cuatro herramientas. Si ya las tienes, salta directo al paso 2.

Herramienta Versión mínima Para qué se usa Dónde descargar
Git 2.x Clonar el repositorio git-scm.com/downloads
Docker Desktop 4.x Correr MySQL y MongoDB en contenedores docker.com/products/docker-desktop
Python 3.11 o 3.12 Correr el backend FastAPI python.org/downloads
Node.js 18 LTS o 20 LTS Correr el frontend React con Vite nodejs.org/en/download
💡
Al instalar Python en Windows, marca la casilla "Add Python to PATH" antes de hacer clic en Instalar. Si no lo haces, la terminal no reconocerá el comando python.

Verificar que todo está instalado

Abre una terminal (PowerShell o CMD) y corre estos comandos. Cada uno debe devolver un número de versión:

git --version
# git version 2.47.1.windows.2

docker --version
# Docker version 27.x.x

python --version
# Python 3.12.x

node --version
# v20.x.x

npm --version
# 10.x.x
⚠️
Docker Desktop debe estar abierto y corriendo (ícono en la bandeja del sistema) antes de ejecutar cualquier comando de Docker. Si está cerrado, los comandos fallarán.

2 Clonar el Repositorio

Elige una carpeta donde quieras guardar el proyecto (por ejemplo C:\proyectos\) y clona el repo:

# Navega a donde quieras guardar el proyecto
cd C:\proyectos

# Clona el repositorio
git clone https://github.com/TU_USUARIO/ProyectoDB2_Guichos.git

# Entra a la carpeta del proyecto
cd ProyectoDB2_Guichos

La estructura del proyecto que verás es esta:

ProyectoDB2_Guichos/
├── backend/          # FastAPI (Python)
│   ├── app/
│   ├── scripts/
│   ├── requirements.txt
│   └── .env.example
├── frontend/         # React + Vite

│   └── mongo/        # colecciones e índices
├── docs/             # Informes y documentación
├── docker-compose.yml
└── .env.example

3 Levantar las Bases de Datos con Docker

Todo lo de MySQL y MongoDB corre en contenedores Docker. Un solo comando levanta ambas bases de datos, las crea, y carga el schema + seed automáticamente.

3.1 Crear el archivo .env del proyecto

En la raíz del proyecto (donde está el docker-compose.yml), copia el archivo de configuración:

# Desde la raíz del proyecto
copy .env.example .env

El archivo .env de la raíz controla las contraseñas de Docker. Los valores por defecto ya funcionan sin cambiar nada:

# Contenido de .env (raíz del proyecto)
MYSQL_ROOT_PASSWORD=rootpassword
MYSQL_DATABASE=tiendaya
MYSQL_USER=tiendaya
MYSQL_PASSWORD=tiendaya123
MYSQL_PORT=3307

MONGO_ROOT_USER=admin
MONGO_ROOT_PASSWORD=adminpassword
MONGO_DATABASE=tiendaya

3.2 Levantar los contenedores

# Desde la raíz del proyecto
docker compose up -d

Docker va a descargar las imágenes (solo la primera vez, tarda unos minutos) y luego arrancar 4 contenedores:

Contenedor Puerto Descripción
tiendaya_mysql 3307 MySQL 8 — base de datos relacional (usuarios, pedidos, inventario)
tiendaya_mongo 27017 MongoDB 7 — catálogo de productos e historial de eventos
tiendaya_adminer 8080 Interfaz web para ver MySQL en el navegador
tiendaya_mongo_express 8081 Interfaz web para ver MongoDB en el navegador

3.3 Verificar que los contenedores están corriendo

docker compose ps

Debes ver los 4 contenedores con estado healthy o running. MySQL tarda ~30 segundos en estar listo la primera vez porque ejecuta los scripts SQL automáticamente.

✅
¿Qué hace Docker automáticamente? Al arrancar por primera vez, MySQL ejecuta los 4 archivos de database/mysql/ en orden: crea todas las tablas (schema), agrega índices, crea los stored procedures, y carga los datos de prueba (seed) con 17 usuarios, productos y pedidos de ejemplo.

3.4 Detener los contenedores (cuando termines)

docker compose stop    # para sin borrar datos
docker compose down    # para y borra contenedores (los datos en volúmenes se conservan)

4 Configurar y Correr el Backend

El backend es una API REST en FastAPI (Python). Necesita su propio entorno virtual con las dependencias instaladas.

4.1 Entrar a la carpeta del backend

cd backend

4.2 Crear entorno virtual de Python

python -m venv venv

Esto crea una carpeta venv/ dentro de backend/. Solo se hace una vez.

4.3 Activar el entorno virtual

# En PowerShell:
.\venv\Scripts\Activate.ps1

# En CMD:
.\venv\Scripts\activate.bat

# En Git Bash:
source venv/Scripts/activate

Sabes que está activado cuando el prompt de la terminal muestra (venv) al inicio.

⚠️
Si PowerShell da error sobre "la ejecución de scripts está deshabilitada", corre este comando primero: Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

4.4 Instalar dependencias

pip install -r requirements.txt

Esto instala FastAPI, SQLAlchemy, PyMongo, JWT, bcrypt y todas las demás librerías. Tarda 1–2 minutos la primera vez.

4.5 Crear el archivo .env del backend

copy .env.example .env

El .env del backend ya tiene los valores correctos para conectarse a Docker:

# Contenido de backend/.env (no cambies nada)
MYSQL_HOST=localhost
MYSQL_PORT=3307       # puerto que expone Docker
MYSQL_DB=tiendaya
MYSQL_USER=tiendaya
MYSQL_PASSWORD=tiendaya123

MONGO_URI=mongodb://admin:adminpassword@localhost:27017/tiendaya?authSource=admin
MONGO_DB=tiendaya

SECRET_KEY=cambia_esto_por_una_clave_segura_de_al_menos_32_caracteres

4.6 Arrancar el servidor

uvicorn app.main:app --reload --port 8001

Debes ver algo como esto:

INFO:     Will watch for changes in these directories: [...]
INFO:     Uvicorn running on http://127.0.0.1:8001
INFO:     Started reloader process using WatchFiles
INFO:     Application startup complete.
💡
El --reload hace que el servidor se reinicie automáticamente cada vez que edites un archivo Python. Es ideal para desarrollo. Deja esta terminal abierta mientras usas la app.

4.7 Verificar que el backend responde

Abre otra terminal y corre:

curl http://localhost:8001/health
# Respuesta esperada: {"status":"ok","version":"1.0.0"}

También puedes abrir http://localhost:8001/docs en el navegador para ver la documentación interactiva de la API (Swagger UI).

5 Poblar MongoDB con el Catálogo de Productos

MySQL se pobla automáticamente con Docker, pero los productos del catálogo necesitan migrarse a MongoDB con un script. Solo se hace una vez.

⚠️
Asegúrate de que Docker esté corriendo (docker compose up -d) Y que el backend haya arrancado al menos una vez antes de correr este script. El script usa la misma conexión a MongoDB que el backend.

5.1 Migrar productos de MySQL a MongoDB

Desde la carpeta backend/ con el venv activado:

python scripts/migrate_products_to_mongo.py --reset

El flag --reset borra cualquier dato previo en MongoDB antes de insertar. Esto migra los 65 productos del seed de MySQL a la colección catalogo en MongoDB, con todos sus atributos, imágenes y categorías.

5.2 Generar el historial de eventos

python scripts/seed_mongo_events.py

Crea eventos históricos de ejemplo en la colección producto_eventos (cambios de precio, actualizaciones de descripción, etc.).

5.3 Verificar que todo está correcto

python scripts/verify_setup.py

Este script comprueba que MySQL tiene datos, MongoDB tiene productos, y que la API responde. Debe terminar sin errores.

✅
Después de este paso, MongoDB tendrá 65 documentos en la colección catalogo con atributos heterogéneos (laptops, libros, ropa, alimentos, etc.) y varios documentos en producto_eventos.

6 Instalar y Correr el Frontend

El frontend es una SPA en React 18 + Vite. Necesita Node.js y npm.

6.1 Abrir una nueva terminal y entrar al frontend

# Desde la raíz del proyecto
cd frontend

6.2 Instalar dependencias

npm install

Descarga todas las librerías de package.json (React, TailwindCSS, Radix UI, Lucide, TanStack Query, etc.). Tarda 1–2 minutos la primera vez.

6.3 Arrancar el servidor de desarrollo

npm run dev

Debes ver:

  VITE v5.x  ready in 800 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: http://192.168.x.x:5173/
💡
Vite tiene un proxy configurado que redirige todas las peticiones /api/* al backend en localhost:8001. No necesitas configurar nada extra para que el frontend hable con la API.

9 Errores Comunes y Soluciones

Error Causa Solución
docker: command not found Docker Desktop no está instalado o no está en PATH Instala Docker Desktop y reinicia la terminal
Error response: port already in use El puerto 3307, 27017 u 8001 ya está ocupado por otro proceso Cierra la aplicación que usa ese puerto, o cambia el puerto en .env
uvicorn: command not found El venv no está activado Activa el venv con .\venv\Scripts\activate antes de correr uvicorn
ModuleNotFoundError: No module named 'app' Estás corriendo uvicorn desde una carpeta incorrecta Asegúrate de estar dentro de la carpeta backend/ cuando corres uvicorn
Frontend muestra "Error de conexión" El backend no está corriendo Asegúrate de que uvicorn esté corriendo en otra terminal
Catálogo vacío (0 productos) No se ejecutó el script de migración de MongoDB Corre python scripts/migrate_products_to_mongo.py --reset
Access denied for user 'tiendaya' MySQL aún no terminó de inicializarse Espera 30–60 segundos y vuelve a intentar. Verifica con docker compose ps
Página en blanco en el navegador Error de JavaScript en el frontend Abre las DevTools (F12), revisa la consola para ver el error específico

10 Queries de Referencia

Queries útiles para explorar los datos directamente en las bases de datos.

MySQL — Queries principales

-- Ver todos los usuarios con sus roles
SELECT u.id, u.nombre, u.email, u.estado,
       GROUP_CONCAT(r.nombre) AS roles
FROM usuarios u
LEFT JOIN usuario_rol ur ON u.id = ur.usuario_id
LEFT JOIN roles r ON ur.rol_id = r.id
GROUP BY u.id;
-- Ver pedidos con su estado y total
SELECT p.id, p.estado, p.total, p.fecha_pedido,
       u.nombre, u.email
FROM pedidos p
JOIN usuarios u ON p.usuario_id = u.id
ORDER BY p.fecha_pedido DESC
LIMIT 10;
-- Ver líneas de un pedido con la referencia a MongoDB
SELECT pl.linea_id, pl.producto_ref, pl.producto_nombre,
       pl.cantidad, pl.precio_unitario,
       (pl.cantidad * pl.precio_unitario) AS subtotal
FROM pedido_lineas pl
WHERE pl.pedido_id = 1;
-- Inventario actual por producto
SELECT producto_ref, stock_disponible, stock_reservado,
       (stock_disponible + stock_reservado) AS stock_total
FROM inventario
ORDER BY stock_disponible ASC
LIMIT 20;
-- Roles del sistema
SELECT * FROM roles;
-- Tablas del sistema
SHOW TABLES;

MongoDB — Queries en mongosh

Conéctate al contenedor de MongoDB con:

docker exec -it tiendaya_mongo mongosh "mongodb://admin:adminpassword@localhost:27017/tiendaya?authSource=admin"
// Ver un producto del catálogo con todos sus atributos
db.catalogo.findOne()

// Ver una laptop específica
db.catalogo.findOne({ "categoria.slug": "computadoras" })

// Contar productos por categoría
db.catalogo.aggregate([
  { $group: { _id: "$categoria.slug", total: { $sum: 1 } } },
  { $sort: { total: -1 } }
])

// Ver el historial de eventos de un producto
db.producto_eventos.find(
  { producto_id: "<PEGAR_EL_ID_DEL_PRODUCTO>" }
).sort({ timestamp: 1 })

// Estadísticas del catálogo con $facet
db.catalogo.aggregate([
  { $facet: {
    por_categoria: [
      { $group: { _id: "$categoria.slug", total: { $sum: 1 }, precio_promedio: { $avg: "$precio" } } },
      { $sort: { total: -1 } }
    ],
    resumen_global: [
      { $group: { _id: null,
          total_productos: { $sum: 1 },
          precio_promedio: { $avg: "$precio" }
      }}
    ]
  }}
])

// Ver los índices creados
db.catalogo.getIndexes()

// Buscar por texto en nombre o descripción
db.catalogo.find({ $text: { $search: "laptop gaming" } })

// Listar todas las colecciones
show collections
